# Organise work by project and knowledge by concept

The PARA-versus-evergreen dispute goes away if each principle governs a different layer. Material for getting work done belongs in project folders, one home per item, because speed of retrieval for a live task is what matters there. Knowledge you want to compound belongs in concept pages with associative links, because it has to outlive any single project. This vault already splits that way: `mine/projects/` on one side, `wiki/` on the other.

## Why I think this
- Forte's case for projects is about finding "all the notes, documents, assets" for the task in front of you ([[raw/forte-para-method.md]]).
- Matuschak's case is about notes that "accumulate over time, across projects" and lead to "better thinking" ([[raw/matuschak-evergreen-notes.md]]).
- PARA itself keeps a topic-based "resources" category, so Forte doesn't reject topic organisation outright ([[raw/forte-para-method.md]]).
- Risk: this reading makes the disagreement look smaller than it is. Forte's hierarchy and Matuschak's "associative over hierarchical" still clash inside a single layer.
