# Organise working material by project and lasting knowledge by concept

Forte and Matuschak disagree about how to organise, but they optimise for different things: Forte for finding everything a live task needs, Matuschak for ideas that build up across projects. Splitting by layer lets each rule govern what it is good at: project folders for working material, concept pages with associative links for knowledge meant to last. Forte doesn't accept the split, since he offers PARA for any information, so this is a choice rather than a middle ground both authors would sign.

## Why I think this
- Forte: for a project you need "all the notes, documents, assets, and other material related to that project all in one place and ready to go" ([[raw/forte-para-method.md]]).
- Forte offers PARA for "organizing any type of digital information across any platform" ([[raw/forte-para-method.md]]).
- Matuschak: evergreen notes "accumulate over time, across projects"; the hub page lists "Evergreen notes should be concept-oriented", "Evergreen notes should be densely linked" and "Prefer associative ontologies to hierarchical taxonomies" as principles ([[raw/matuschak-evergreen-notes.md]]).
- (reasoning) Speed on a live task and compounding across tasks pull toward different structures, so one structure for both serves one of them badly.
- (reasoning) This vault already splits this way: `mine/projects/` for work, concept pages in `wiki/` for knowledge.
- Limit: inside one layer the clash remains. A concept page still has no single hierarchical home.
